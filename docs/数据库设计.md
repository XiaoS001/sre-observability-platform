# 数据库设计 · RMB03

> 引擎：SQLite（默认，`data/rmb03.db`）
> ORM：SQLAlchemy 2.0 + Flask-SQLAlchemy 3.1
> 🔴 本库是**本项目自己新建的**，与 XM01 的 `app.db`、XM05 的 `xm01_copy.db` 无关

## 一、ER 关系

```
        ┌──────────┐
        │  role    │ 1
        └────┬─────┘
             │ N
        ┌────┴─────┐
        │   user   │
        └──────────┘

  ┌──────────┐ 1      N ┌──────────────┐
  │  target  ├──────────►│ check_record │
  └────┬─────┘           └──────────────┘
       │ 1
       │ N
  ┌────┴──────┐ 1     N ┌───────┐ 1      N ┌──────────────┐
  │ alert_rule├─────────►│ alert ├─────────►│ notification │
  └───────────┘          └───────┘          └──────────────┘
```

`target` 是聚合根：巡检记录、告警规则、告警都挂在它下面。
删除 target 会级联删除它的记录与规则（`cascade='all, delete-orphan'`）。

## 二、七张表

### `target` · 监控目标

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `name` | VARCHAR(200) | NOT NULL | 显示名 |
| `url` | VARCHAR(500) | NOT NULL | 被巡检地址 |
| `timeout` | INTEGER | NOT NULL, default 5 | 请求超时（秒） |
| `interval_seconds` | INTEGER | NOT NULL, default 60 | **巡检间隔（秒）** |
| `enabled` | BOOLEAN | NOT NULL, default true | 是否参与调度 |
| `created_at` | DATETIME | NOT NULL | |

> `interval_seconds` 挂在目标上而不是全局 —— 每个目标可以有独立频率。
> 入口校验 `> 0`：`<= 0` 会被调度器当成「总是到点」，等于变相全速巡检。

### `check_record` · 巡检记录

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `target_id` | INTEGER | FK → target.id, **index** | |
| `status_code` | INTEGER | NULL | 无响应时为 NULL |
| `duration_ms` | FLOAT | NOT NULL | 耗时 |
| `is_success` | BOOLEAN | NOT NULL | 成功区间 `[200, 399]` |
| `error_msg` | VARCHAR(500) | NULL | **失败四分类靠它的前缀** |
| `checked_at` | DATETIME | NOT NULL, **index** | |

### `alert_rule` · 告警规则

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `target_id` | INTEGER | FK → target.id, **index** | |
| `name` | VARCHAR(200) | NOT NULL | |
| `rule_type` | VARCHAR(50) | NOT NULL | 三种类型之一 |
| `threshold` | FLOAT | NOT NULL | **单位随 rule_type 变** |
| `enabled` | BOOLEAN | NOT NULL, default true | |
| `created_at` | DATETIME | NOT NULL | |

### `alert` · 触发的告警

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `rule_id` | INTEGER | FK → alert_rule.id, **index** | |
| `target_id` | INTEGER | FK → target.id, **index** | 冗余存一份，查询不必 join |
| `message` | VARCHAR(500) | NOT NULL | 人读文案 |
| `observed_value` | FLOAT | NULL | 触发时实测值 |
| `threshold` | FLOAT | NULL | 触发时阈值快照 |
| `reason` | VARCHAR(50) | NULL | 失败分类（timeout/connect/…） |
| `triggered_at` | DATETIME | NOT NULL, **index** | |
| `resolved_at` | DATETIME | NULL | NULL = 进行中 |

> 存 `threshold` 快照而不是 join 规则表：规则后来被改了，历史告警
> 仍要显示「当时」的阈值，否则事后复盘会看到错误的对比。

### `notification` · 通知投递记录

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `alert_id` | INTEGER | FK → alert.id, **index** | |
| `channel` | VARCHAR(50) | NOT NULL | `webhook` / `email` |
| `target_url` | VARCHAR(500) | NULL | 投递地址 |
| `success` | BOOLEAN | NOT NULL | **失败也落库** |
| `status_code` | INTEGER | NULL | |
| `error_msg` | VARCHAR(500) | NULL | 失败原因 |
| `sent_at` | DATETIME | NOT NULL | |

> 一条告警 × 一个渠道 = 一条记录。**发送失败必须留痕** ——
> 否则「告警了但没人收到」这类问题无从排查。

### `role` · 角色字典

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | INTEGER | PK |
| `name` | VARCHAR(50) | NOT NULL, **unique** |
| `description` | VARCHAR(200) | NOT NULL |

内置三条（`init_roles()` 幂等写入）：

| name | 说明 |
|---|---|
| `admin` | 管理员：全部权限，含用户管理 |
| `operator` | 运维：可管目标与规则，不可管用户 |
| `viewer` | 只读：只看状态页与报表，**看不到告警规则详情** |

> 角色存**字符串**而非自增 id：它是固定的业务枚举，写在代码里更直观，
> 也避免「库被清空后角色 id 漂移」。

### `user` · 用户

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | INTEGER | PK |
| `username` | VARCHAR(100) | NOT NULL, **unique** |
| `password_hash` | VARCHAR(255) | NOT NULL |
| `role_id` | INTEGER | FK → role.id, NOT NULL |
| `created_at` | DATETIME | NOT NULL |

## 三、失败四分类（跨表一致性）

`metrics._classify_failure(status_code, error_msg)` 是**唯一**的分类来源，
被三处复用，保证「指标里的 reason 能直接在日志和告警里搜到同一个值」：

| 输入条件 | `reason` |
|---|---|
| `error_msg` 以 `请求超时:` 开头 | `timeout` |
| `error_msg` 以 `连接失败:` 开头 | `connect` |
| `error_msg` 以 `请求异常:` 开头 | `exception` |
| 有 `status_code` 但无上述前缀 | `bad_status` |
| 全空（脏数据） | `exception`（兜底，不返回 None） |

## 四、索引与查询模式

| 场景 | 走哪个索引 |
|---|---|
| 某目标最近一次巡检 | `check_record(target_id, checked_at)` |
| 可用率/P95 窗口聚合 | `check_record(target_id, checked_at)` |
| 冷却判定「最近一条告警」 | `alert(rule_id, target_id)` + `triggered_at` |
| 状态页每日可用率 | `check_record(checked_at)` |
| 报表按天聚合 | `check_record(checked_at)` |

## 五、测试隔离

🔴 **测试绝不能写 `data/rmb03.db`**。

做法：`tests/conftest.py` **模块级**设 `RMB03_DATABASE_URL` 指向
`tests/_tmp_testdata/test.db`。

必须是模块级而非 fixture 内 —— pytest 收集阶段会先 import 各 `test_*.py`，
其中 `import scheduler` 会连锁 import `config`，而 `config` 在 import 那一刻
就把 `DATABASE_URL` 读成了模块级常量。等 fixture 跑完再设已经太晚。

隔离有效性有**硬断言**兜底：测试库路径与真实库相同、或 `config.DATABASE_URL`
未指向测试库时，测试直接失败而不是放行。

> ✅ 实测：跑完全部 167 条测试后 `data/rmb03.db` 时间戳未变。

## 六、备份与恢复

```bash
# 备份（SQLite 在线备份，不停服）
sqlite3 data/rmb03.db ".backup 'backups/rmb03-$(date +%Y%m%d-%H%M%S).db'"

# 恢复
cp backups/rmb03-20261016-220000.db data/rmb03.db
```

> ⚠️ 不要直接 `cp` 正在写入的 db 文件（可能拷到半个事务）。
> 用 `.backup` 命令或停服后拷贝。
